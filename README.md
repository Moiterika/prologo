# トランプ 3 種 — Prolog ルール + GoTH (Go / templ / htmx)

CPU と対戦できるハート・大富豪・ナポレオン。
**ゲームのルール判定はすべて Prolog 側**にあり、Go は純 Go 実装の Prolog 処理系
[ichiban/prolog](https://github.com/ichiban/prolog) にルールファイルを読み込ませて、
シャッフル・進行管理・画面の描画だけを担当する。

画面は templ + htmx。WebSocket もデータベースも使わない。
ブラウザからの POST でゲームを 1 手進め、その場で描き直して返すだけ。

| ゲーム | URL | 中身 |
| --- | --- | --- |
| (ゲーム選択) | `/` | 3 つのゲームを並べた入口。対局の途中のゲームには「対局中」の印が付く |
| ハート | `/hearts` | CPU 3 人と失点を競るトリックテイキング |
| 大富豪 | `/daifugo` | ローカルルールを選んで CPU と手札を出し切る競争 |
| ナポレオン | `/napoleon` | 競りでナポレオンを決め、絵札 20 枚を奪い合う |

大富豪とナポレオンの CPU は、一部の場面を除いて合法手のなかからランダムに選ぶだけで、
先を読む思考は持たない (→ [CPU の思考](#cpu-の思考))。

## 遊び方

Go 1.26.4 以上が必要 (`go.mod` の指定)。Go 1.27.4 でビルドとテストが通ることを確認している。

```
go build -o game.exe ./cmd/game
./game.exe
```

起動したら http://127.0.0.1:8080/ を開き、遊ぶゲームを選ぶ。
遊び始めてからもヘッダーで 3 つのゲームを行き来できる (ゲームを移っても対局は残る)。
対局をやめるときは盤面右上の「終了してゲーム選択へ」を押す。
その対局は消え、ゲームを選ぶ画面に戻る。

どのゲームも、まずルール選択の画面になる。画面の先頭には
「基本ルールのみ」「作者オススメ」の 2 つのプリセットがある。
大富豪とナポレオンはローカルルールが多いので、初めてなら「基本ルールのみ」を
押してから始めるとよい (→ [ハート](#ハート) / [大富豪](#大富豪) / [ナポレオン](#ナポレオン))。

`Makefile` も置いてあるが (`make run` / `make test` / `make doc-http` …)、
`make` が入っていない環境でも困らないよう、以下では素の `go` コマンドを併記する。
括弧内が対応する make のターゲット。

| オプション | 意味 |
| --- | --- |
| `-addr 127.0.0.1:8080` | 待ち受けアドレス |
| `-limit 100` | ハート: この失点に達したらゲーム終了 |
| `-players 4` | ハート: 人数 3 / 4 / 5 (`hearts.pl` の `game_config/4` に対応) |
| `-games 5` | 大富豪・ナポレオン: 通して遊ぶゲーム数 |
| `-seed 42` | 乱数シード (同じ配札を再現できる) |
| `-pl internal/rules` | 埋め込みではなくこのディレクトリの `.pl` を読む |

`-pl` を付ければ、再ビルドせずに `.pl` を書き換えて挙動を試せる。
ただし読むのはそのディレクトリ直下だけなので、ゲームごとに
`-pl internal/rules` / `-pl internal/rules/daifugo` / `-pl internal/rules/napoleon`
のいずれかを指す (共通の `compat.pl` は常に埋め込みから読む)。

`.templ` を編集したときは `go tool templ generate` (make generate)。
生成物の `*_templ.go` はコミットしてあるので、通常のビルドでは不要。

## エンドポイント

ゲームごとに URL の頭を揃えてある。`{game}` は `hearts` / `daifugo` / `napoleon`。

| メソッドとパス | 動作 |
| --- | --- |
| `GET /` | ゲームを選ぶ画面 |
| `GET /{game}` | 対局中なら盤面、そうでなければルール選択の画面 |
| `POST /{game}/start` | 選んだルールで始める |
| `POST /{game}/preset` | ルール選択の画面で、選択をプリセットに置き換える |
| `POST /{game}/new` | 同じルールで最初からやり直す |
| `POST /{game}/setup` | 対局を捨ててルール選択の画面に戻る |
| `POST /{game}/quit` | 対局を捨てて `/` へリダイレクトする |
| `POST /{game}/next` | トリック・ゲームの区切りから先へ進む |
| `POST /{game}/play` | カードを出す |

ほかにゲーム固有の操作がある。

| ゲーム | パス |
| --- | --- |
| ハート | `/hearts/pass` (カード交換) |
| 大富豪 | `/daifugo/pass` `/daifugo/exchange` `/daifugo/jackback` `/daifugo/ten-discard` `/daifugo/seven-give` |
| ナポレオン | `/napoleon/bid` `/napoleon/aide` `/napoleon/discard` |

どの POST 先も、GET で来たら `/{game}` へリダイレクトする
(→ [internal/web — 画面](#internalweb--画面))。

## ディレクトリ構成

```
cmd/game/                  エントリポイント (フラグ処理とサーバー起動)
internal/cards/            カード 1 枚の表現と Prolog 項との変換 (3 ゲーム共通)
internal/plog/             Prolog 処理系の薄いラッパと compat.pl (3 ゲーム共通)
internal/playerr/          「入力がルール上おかしい」誤り (3 ゲーム共通)
internal/rules/            ハートのルール判定 (.pl 本体と Prolog ブリッジ)
internal/rules/daifugo/    大富豪のルール判定
internal/rules/napoleon/   ナポレオンのルール判定
internal/game/             ハート 1 局分の進行 (状態機械)
internal/game/daifugo/     大富豪の進行
internal/game/napoleon/    ナポレオンの進行
internal/web/              HTTP ハンドラとセッション
internal/web/view/         templ による画面
```

依存の向きは `cmd → web → game → rules → (cards, plog)` の一方向。
`rules` は `game` や `web` を参照せず、`game` も `web` や `net/http` を参照しない。

`rules.Engine` (Prolog インタプリタを包んだもの) は並行安全ではないので、
同時に進む対局どうしで共有するわけにはいかない。web 層ではセッションごと・
ゲームごとに 1 つ持ち、同じセッションで対局をやり直すときは使い回す。
こうすれば別々のブラウザから同時にアクセスしても状態が混ざらない。
Engine はそのゲームを最初に開いたときに作る
(ハートしか遊ばない人に大富豪とナポレオンの `.pl` を読ませても仕方がない)。

### 共通の土台

| ファイル | 役割 |
| --- | --- |
| `internal/plog/compat.pl` | ichiban/prolog は ISO 準拠なので、SWI 固有の `:- dynamic` 前置演算子や `include/3`, `flatten/2`, `forall/2`, `intersection/3` などをここで補う。どのゲームの `.pl` より先に必ず読み込まれる |
| `internal/plog/plog.go` | `.pl` の読み込みと問い合わせ。個々のゲームのルールには依存しない |
| `internal/cards/cards.go` | `card(Suit, Rank)` ↔ Go の `Card`。ジョーカーは `card(joker, …)` |

3 つのゲームはどれも Prolog 側で `card(Suit, Rank)` という同じ形の項を使う。
ジョーカーはスートを `joker`、ランクを専用のアトム (`jk1` / `jk2` / `jk`) にしてある。
ランクを専用のアトムにしたのは、`card(_, 2)` のようなパターンがうっかり
ジョーカーに当たらないようにするため。

### ハート — internal/rules

| ファイル | 役割 |
| --- | --- |
| `hearts.pl` | 最初のコミットから中身を 1 行も変更していない (SWI-Prolog 向けの記述との差は `compat.pl` で吸収する)。カードの強さ、点数 (`card_point/2`)、マストフォロー (`can_play/3`)、トリックの勝者 (`determine_winner/3`)、採点 (`calculate_score/2`)、配札の検証 (`validate_deal/1`)、人数設定 (`game_config/4`) |
| `hearts_rules.pl` | `hearts.pl` を書き換えず、その述語を呼び出して組み立てた追加ルール。デッキ生成、第 1 トリックの流儀、ハートブレイク、カード交換 (パス)、スラム、終了判定 |
| `hearts_ai.pl` | CPU の思考。`rank_value/2`, `is_stronger/2`, `determine_winner/3` をそのまま使ってカードを選ぶ |

読み込み順は `compat.pl → hearts.pl → hearts_rules.pl → hearts_ai.pl`。

### 大富豪 — internal/rules/daifugo

| ファイル | 役割 |
| --- | --- |
| `daifugo.pl` | 基本ルールだけ。カードの強さ (革命による反転を含む)、出し方 (役) の判定 `classify/7`、場に勝てるか `beats/4`、称号 `title/3`、交換 `exchange/4`、配札の検証 |
| `daifugo_rules.pl` | ローカルルールを重ねる層。設定は全て動的述語で、`set_*` で書き換える。合法手の判定は `resolve_play/6` ひとつに集約してある |
| `daifugo_ai.pl` | 合法手を列挙して、Go から渡した種でランダムに 1 つ選ぶ。10捨て・7渡しで CPU が手放す札も選ぶ |

読み込み順は `compat.pl → daifugo.pl → daifugo_rules.pl → daifugo_ai.pl`。

### ナポレオン — internal/rules/napoleon

| ファイル | 役割 |
| --- | --- |
| `napoleon.pl` | 基本ルールだけ。三役 (♠A・正J・裏J) を含む強さ `base_power/4`、マストフォロー `can_play/3`、トリックの勝者 `strongest/4`、絵札 `point_card/1`、宣言の強弱 `bid_stronger/4` |
| `napoleon_rules.pl` | ローカルルールを重ねる層。ジョーカーの強さ `power/4`、台札の請求 `lead_requirement/3`、例外規定つきの勝者判定 `trick_winner/5`、精算 `round_scores/7` |
| `napoleon_ai.pl` | カードは原則ランダム。競り・副官指名・埋め札・セイムツーの 2 だけ選び方を変える |

読み込み順は `compat.pl → napoleon.pl → napoleon_rules.pl → napoleon_ai.pl`。

### internal/game — 進行

どのゲームも状態機械で、画面や HTTP には依存しない。ルール判定も自分では書かず、
すべて Prolog に問い合わせる。局面は次のとおり。

| ゲーム | 局面 |
| --- | --- |
| ハート | `passing` / `playing` / `trick_done` / `round_done` / `game_over` |
| 大富豪 | `exchange` / `playing` / `jack_back` / `ten_discard` / `seven_give` / `round_end` / `game_over` |
| ナポレオン | `bidding` / `naming` / `discarding` / `playing` / `trick_done` / `round_done` / `game_over` |

プレイヤーの入力ミスは `playerr.Error` で返し、web 側が 500 ではなく
画面上のメッセージとして出す。

### internal/web — 画面

- **htmx**: `<body>` に `hx-boost` を付けてあるので、テンプレート側は素の
  `<form method="post">` を書くだけでよい。応答から `#app` を取り出して差し替える。
  JavaScript を切っても普通のフォーム送信としてそのまま遊べる。
  ヘッダーのゲーム切り替え、ゲームを選ぶ画面のリンク、「終了してゲーム選択へ」は
  ページ遷移なので `hx-boost="false"`。終了は `POST /{game}/quit` が `/` へ
  リダイレクトし、確認は素の `confirm()` で出す (htmx を通さないので `hx-confirm` は使えない)。
- **`hx-push-url="false"`**: 既定だと POST 先の URL がアドレス欄に載り、
  そこでリロードすると `GET /hearts/play` になってしまう。ゲームの状態はすべて
  サーバー側にあり履歴に意味が無いので URL は動かさない。
  (念のため `GET /hearts/play` などは `/hearts` へリダイレクトする)
- **セッション**: Cookie (`cards_session`) の ID でプロセス内のメモリに紐付ける。
  3 つのゲームの対局を 1 つのセッションにまとめて持つ。
- **円卓** (ハート・ナポレオン): 3x3 のグリッドに席を置き、「あなた」を必ず
  手前 (下段中央) にする。出したカードは名札の中央寄りに並ぶので、
  誰が出した札かが分かる。
- **場** (大富豪): トリックの区切りが無く、1 回の応答で CPU が何人も続けて
  手を出す。直前の 1 手だけでは何が起きたか分からないので、場が流れるまでの
  手を「誰が・何を」の形で順に並べる (パスも枠だけ残す)。いちばん新しい手には
  「いまの場」の印を付ける。その下に直近 10 件の履歴も出す。
- **強さの並び** (大富豪): 革命や Jバックに気づかないまま「出せるはずなのに
  出せない」で悩まないよう、今の強さの並び (`3 < 4 < … < 2 < JOKER`) を
  盤面に常に出す。反転しているあいだは赤く、理由も添える。
  革命と Jバックが重なって反転が打ち消し合っている場合もそう書く。
- **出せない札を薄く** (大富豪): 今の場に出せる手に使えないカードは薄くする。
  ただし選べるままにしてある (合法手の列挙はジョーカーの使い回しまでは
  作らないので、薄い札が絶対に出せないとまでは言い切れない)。
- **サーバー側のログ** (大富豪): 画面に残るのは直近 10 件だけなので、
  進行の控えを標準のログにも流す。セッションの短い目印とゲーム番号が付く。

  ```
  大富豪[f6c7c2] 第1ゲーム CPU1 が出しました [♥J]
  大富豪[f6c7c2] 第1ゲーム Jバック! 場が流れるまで強弱が反転します
  大富豪[f6c7c2] 第1ゲーム CPU2 が出しました [♣3]
  ```

  ハートとナポレオンはトリックごとに止まって盤面に全員の手が出るので、
  控えは取っていない。

## 実装されているルール

### ハート

- ♥ 1 枚 = 1 点、♠Q = 13 点。失点が少ないほど良い
- 台札と同じスートを持っていたら必ず出す (マストフォロー)
- 毎ラウンド 3 枚交換 (左 → 右 → 向かい → 交換なし の 4 周期。奇数人数では左 → 右 → 交換なし)
- スラム (1 人で全 26 点を独占 → 本人 0 点、他全員 26 点)
- 誰かが上限点に達したら終了、最少失点が勝ち

3 人戦では ♣2 を除いた 51 枚 17 枚ずつ、5 人戦では ♣2 と ♦2 を除いた 50 枚 10 枚ずつ
(`hearts.pl` の `game_config/4` どおり)。開始カードは ♣2 が無い人数では ♣3 になる。

#### 開始時に選べる流儀

判定は Prolog 側 (`hearts_rules.pl` の `first_trick_points/1`, `first_trick_lead/1`,
`hearts_break_rule/1`) が持つ。

| 問い | 選べる値 |
| --- | --- |
| 第1トリックのリード | ♣2 から始める (既定) / ♣2 を持つ人が自由に出せる |
| 第1トリックに点数札を出せるか | 点数札許可 (既定) / ♥ のみ禁止 / 点数札禁止 |
| ハートブレイク | なし (既定) / あり |

画面の先頭にプリセットが 2 つある。

| プリセット | 第1トリックのリード | 点数札 | ハートブレイク |
| --- | --- | --- | --- |
| 基本ルールのみ (= 既定) | ♣2 から | 許可 | なし |
| 作者オススメ | ♣2 から | 禁止 (no blood) | あり |

大富豪・ナポレオンと違い、ハートは既定の流儀がそのまま「基本ルールのみ」に
当たる (`hearts.pl` に追加の制限を足さない形)。そのため「作者オススメ」は
既定ではなく、よく遊ばれている流儀の組み合わせにしてある。

どの流儀でも、禁止されたカードしか持っていない場合は出さざるを得ないので許される。
ブレイクの引き金は「ハートが出たとき」ではなく「得点札が出たとき」なので、
♠Q が出ただけでもブレイクする (`hearts_rules.pl` の `contains_point_card/1`)。

### 大富豪

- 強さは 3 < 4 < … < K < A < 2 < ジョーカー。マークによる強弱は無い
- 出し方は 単騎 / ペア / スリーカード / フォーカード / 階段 (同じマークで連続する 3 枚以上)
- 場と同じ種別・同じ枚数で、より強いものだけ出せる
- 全員がパスしたら場が流れ、最後に出した人が次の親
- フォーカードで革命 (強弱が反転)。もう一度出ると革命返しで元に戻る
- 手札を出し切った順に称号が決まり、順位点 (1 位が最大、最下位が 0) が入る
- 2 ゲーム目からは称号に応じてカードを交換する (大富豪 ⇔ 大貧民 2 枚、富豪 ⇔ 貧民 1 枚)

#### 開始時に選べるローカルルール

画面の先頭に**プリセット**が 2 つある。「基本ルールのみ」はローカルルールを
すべて外し、「作者オススメ」は下の表の既定 (太字) に戻す。どちらも人数は変えない。
押すとルール選択の画面のまま選択が切り替わるので、そこから個別に直してもよい。

既定は**太字**。選択肢はどれも「なし」を先頭に置いてあるので、
上から下へ読むと「使わない → 盛る」の並びになる。

| 問い | 選べる値 |
| --- | --- |
| 人数 | 3 / **4** / 5 / 6 |
| ジョーカーの枚数 | なし (52枚) / 1 枚 (53枚) / **2 枚 (54枚)** |
| 1 ゲーム目の始め方 | ♦3 を必ず 1 枚出す / **♦3 を持つ人が自由に出す** / 席順の先頭から自由に |
| 8流し (8切り) | なし / **あり・階段の 8 も含む** / あり・階段は対象外 |
| Jバック | なし / **あり・階段の J も含む** / あり・階段は対象外 |
| └ 任意適用にする | **入れる** (外すと強制適用) |
| 階段革命 | なし / **あり (4 枚以上の階段)** |
| ファイブカード・シックスカード | なし / **あり** |
| 縛り | なし / **あり** |
| └ 激縛り | **入れる** |
| └ 片方縛り | **入れる** |
| 10捨て | なし / **あり** |
| 7渡し | **なし** / あり |
| スペ3返し | なし / **あり** |
| パスの処理 | **何度でも出せる** / 一度パスしたら流れるまで出せない |
| 誰かが上がったときの場 | **そのまま続ける** / 上がった瞬間に流す |
| 反則上がり禁止 | なし / **あり** |
| 都落ち | なし / **あり** |

`└` の行はラジオボタンではなくチェックボックス。
本が「縛りの一種」「Jバックの適用の仕方」と書いているとおり、
親の流儀を選んだときにだけ適用される枝分かれなので、画面でも親の下にぶら下げ、
親で「なし」を選んでいるあいだは隠す。
隠す・出すの切り替えは小さなインラインスクリプトで行うが、初期状態は
サーバー側で決めているので、JavaScript を切っていても既定の見え方は正しい
(切っている場合は選び直しても隠れたままになる。隠れた枝分かれは Prolog 側が
無視するので、遊ぶぶんには困らない)。

各ルールの細かい判定は次のとおり。

- **縛り**は「1 つ前と全く同じマーク構成が出たら、以降そのマークを必ず含める」。
  ジョーカーは縛られたマークの代わりになる。
  枝分かれの 2 つは互いに独立していて、両方入れてもよい。
  - **片方縛り**を入れると、マークが一部だけ一致した場合にもそのマークで縛る
    (どのマークで縛られるかが変わる)。
  - **激縛り**を入れると、縛りの発生時に数字がちょうど 1 つ上がっていた場合、
    次はその次の数字しか出せない (数字まで固定される)。
- **Jバック**を「任意適用」にすると、J を出した人がその場で反転させるか決める。
  人間の番なら画面で選び、CPU はランダムに決める。
  本にある「上か下かを宣言する」ハウスルールまでは入れていない。
- **10捨て・7渡し**は、出した 10 (7) の枚数だけ手札を捨てる (次の人へ渡す)。
  階段に含まれる 10 や 7 も数える。捨てる・渡すカードは人間が選び、
  CPU は弱い順に手放す。
- **反則上がり禁止**の禁じ手は、ジョーカー・通常時の 2・革命時の 3。
  8流しを採用していれば 8 も、Jバックを採用していれば J も禁じ手になる
  (`daifugo_rules.pl` の `foul_card/2`)。
  10捨て・7渡しで捨てる枚数を手札が賄えなかった場合も反則
  (同 `foul_shortage/2`)。反則上がりと都落ちは発生順に
  下位 (大貧民・貧民・平民…) から割り当てる。
- **ジョーカー入りの階段**は解釈が複数あり得る (`♠9 JOKER ♠J` の JOKER は
  ♠10 とも読めるし、`♠J ♠Q` の並びの一部とも読める)。
  場に勝てる解釈のうちもっとも弱いものを採用する。ジョーカーを足しただけで
  不必要に強い札とは見なさない、という約束。

本には載っていて未実装のもの: 乞食、防衛 (追徴課税)、
「流れるまで革命は成就しない」流派、カード交換の順序を変える流儀。

### ナポレオン

- 5 人に 10 枚ずつ配り、残りを場に伏せる (埋め札)。4 人なら 12 枚ずつ、6 人なら 8 枚ずつ
- A・K・Q・J・10 の 20 枚が得点カード (絵札)
- 強い順に ♠A (オールマイティ) > 正J > 裏J > 切り札 > 台札 > それ以外
  - 正Jは切り札と同じマークの J、裏Jは同じ色のもう一方のマークの J
- 競りで切り札と宣言枚数を決める。枚数が多いほど強く、同じ枚数なら ♠ > ♥ > ♦ > ♣
- ナポレオンは副官のカードを 1 枚指名する。そのカードが場に出るまで副官は分からない
- ナポレオンは埋め札を手札に加え、同じ枚数を伏せ直す
- 全トリックを終えて、ナポレオン軍の取った絵札が宣言枚数に届けばナポレオン軍の勝ち

指名したカードをナポレオン自身が持っていた場合 (埋め札に入っていた場合を含む) は
副官なしのゲームになる。伏せ直した埋め札は誰も取れないので、
**絵札を伏せるとその分だけナポレオン軍の得点が減る**。

#### 開始時に選べるローカルルール

画面の先頭に**プリセット**が 2 つある。「基本ルールのみ」はローカルルールを
すべて外し、「作者オススメ」は下の表の既定 (太字) に戻す。どちらも人数は変えない。
押すとルール選択の画面のまま選択が切り替わるので、そこから個別に直してもよい。

| 問い | 選べる値 |
| --- | --- |
| 人数 | 5 (既定) / 4 / 6 |
| 最低宣言枚数 | 10 (既定) / 12 / 14 |
| セイムツー | なし / **あり (既定)** |
| └ 切り札では無効 | チェックボックス (既定でチェックあり) |
| よろめき | なし / **あり (既定)** |
| └ よろめき返し | チェックボックス (既定でチェックなし) |
| ジョーカー | 入れない / **2 番手 (既定)** / 最強 / 三役未満 / 最弱 |
| └ ジョーカーの自由出し | チェックボックス (既定でチェックなし) |
| └ 切り札請求 (ジョーカーが台札) | チェックボックス (既定でチェックあり) |
| └ ジョーカー請求 (♠3 が台札) | チェックボックス (既定でチェックなし) |
| 三役の拒否権 | なし / **あり (既定)** |
| 宣言枚数による得点の重み | **なし (既定)** / あり |
| 20 枚独占したとき | 普通に数える (既定) / 得点が 2 倍 / 取った側の負け + 2 倍 |

`└` は枝分かれのチェックボックスで、親の流儀を使うときだけ画面に出る
(セイムツー「なし」を選んでいるあいだは「切り札では無効」を出さない)。

各ルールの細かい判定は次のとおり。

- **セイムツー**は「台札と同じマークだけが出揃い、その中に 2 があればその 2 が勝つ」。
  ジョーカーが混ざると (マークが違うので) 自動的に成立しない。
- **よろめき**は ♠A が本来勝つ場面でだけ起きる例外として実装してある。
  ジョーカーを最強にしている場合、ジョーカーが出ていれば発動しない。
- **三役の拒否権**は「台札のマークが三役しか無ければ、出さずに温存してよい」。
  三役でないカードを持っていれば、普通にマストフォローが適用される。
- 得点はどちらでもゼロサム。
  **重みなし**は『12人目のナポレオン』の方式で、宣言枚数によらず
  ナポレオン ±2 (副官なし ±4)、副官 ±1、連合軍 ∓1。
  **重みあり**は連合軍の点を「宣言枚数 −(最低枚数−1)」とし、
  ナポレオンをその 2 倍 (副官なしなら 4 倍)、副官を同額にする。

本には載っていて未実装のもの: 三役をいつでも出せる流儀、
ジョーカー台札の任意マーク請求・絵札請求。

## CPU の思考

大富豪とナポレオンの CPU は、合法手を列挙して、そこから一様にランダムに選ぶ。
Prolog には乱数が無いので、Go から渡した種 (`Seed`) を選択肢の数で割った余りで
選ぶ形にしてある。どれが合法かの判断は `daifugo_rules.pl` /
`napoleon_rules.pl` に任せてあり、AI 側にルールの知識は置いていない。

ランダムのままでは不都合が出る次の 5 か所だけ、選び方を変えてある。
ランダムを残しているのは競りだけで、ほかの 4 か所は決まった規則で選ぶ
(副官の指名は、候補が尽きた場合だけランダムに戻る)。

- **ナポレオンの競り**: 候補は「パス + 今より 1 段階上の宣言 (4 通りまで)」。
  パスは複数回ぶん入れてあり、その本数は宣言が最低枚数から吊り上がるほど増える。
  一様に選ぶと宣言が 20 枚まで際限なく上がり、ナポレオン軍がまず勝てない
  ゲームになってしまうため (`napoleon_ai.pl` の `bid_candidates/3`)。
- **ナポレオンの副官指名**: 三役 (♠A・正J・裏J) とジョーカーのうち、
  自分が持っていないもののいちばん強い 1 枚を指名する。強さの並びは
  ジョーカーの流儀で変わるので `power/4` に任せてある
  (`napoleon_ai.pl` の `strong_aide_candidates/3`)。
  全部自分の手札にあるときだけ、各マークの A・K からランダムに選ぶ。
- **ナポレオンの埋め札**: 弱い順に伏せる。ランダムだと ♠A を伏せてしまう。
- **大富豪の 10捨て・7渡し**: 手放す札は弱い順に選ぶ
  (`daifugo_ai.pl` の `weakest_cards/3`)。ランダムだと強い札まで手放してしまう。
- **セイムツー**: 採用していて、台札と同じマークだけが出ているあいだに
  そのマークの 2 を持っていたら、迷わずその 2 を出す
  (`napoleon_ai.pl` の `same_two_pick/5`)。ランダムに出していると
  セイムツーがほとんど起きず、採用した意味が無くなるため。
  あとの人にマークを崩されると空振りするが、2 はもともといちばん弱い札
  なので出し損にはならない。

大富豪の合法手の列挙 (`daifugo_ai.pl` の `candidate/2`) は、
「同じ数字の組み合わせ」と「同じマークで連続する窓に入るカード全部」だけを作る。
手札の全部分集合を試すと組み合わせが爆発するため。
「持っている札をあえてジョーカーで置き換える」ような手は作らないが、
人間が選んだ手は `resolve_play/6` が個別に判定するので取りこぼしにはならない。

ハートの CPU は、大富豪とナポレオンを加える前からある簡単なヒューリスティック (`hearts_ai.pl`) のまま。

## ドキュメント

端末に出す場合。

```
go doc -all ./internal/rules             # Example つきの全文    (make doc)
go doc -all ./internal/rules/daifugo
go doc -all ./internal/rules/napoleon
go doc ./internal/rules Engine           # 型だけ
```

ブラウザで見る場合。`go` ツールチェーンにドキュメントサーバーは同梱されていない
(Go 1.13 で `godoc` が本体から外れて `golang.org/x/tools` へ移った) ので、
`go run` で取ってくる。`@latest` なので `go.mod` の依存には入らない。

```
go run golang.org/x/tools/cmd/godoc@latest -http 127.0.0.1:6060    # (make doc-http)
```

起動後、数秒待ってから http://127.0.0.1:6060/pkg/hearts/internal/rules/ を開く。
`internal/` パッケージもそのまま見えて、Example は `// Output:` の中身まで展開される。

### PowerShell から直接実行するときの注意

PowerShell 5.1 は、`-` で始まり `.` を含む引数を `.` の位置で 2 つに分割する。

```
> go run . -http=127.0.0.1:6060
argv[1] = "-http=127"
argv[2] = ".0.0.1:6060"        ← 2 つに割れて「Unexpected arguments」になる
```

クォートするか、スペース区切りにすれば通る。

```powershell
go run golang.org/x/tools/cmd/godoc@latest "-http=127.0.0.1:6060"
go run golang.org/x/tools/cmd/godoc@latest -http 127.0.0.1:6060
```

`game.exe` のフラグも同じなので、`-addr=127.0.0.1:8080` ではなく `-addr 127.0.0.1:8080` と書く
(`-seed=42` のように `.` を含まない値なら割れない)。
`make` 経由なら sh が解釈するのでこの問題は起きない。

### pkgsite (pkg.go.dev と同じ見た目) を使う場合

現行の公式ツールは [pkgsite](https://pkg.go.dev/golang.org/x/pkgsite) だが、
このモジュールはそのままでは表示できない。モジュールパス `hearts` は最初の要素に
ドットが無いため、pkgsite が標準ライブラリのパスと解釈して 424 を返す。

```
go run golang.org/x/pkgsite/cmd/pkgsite@latest -http 127.0.0.1:8090 .
```

使うなら `go.mod` のモジュールパスを `example.com/cards` のような
ドットを含むものに変える必要がある (公開する予定ができたときにリポジトリの URL へ)。
ゲームが 3 つになった今となっては `hearts` という名前自体も実態に合っていないので、
そのときに一緒に直すのがよい。

go test -count=1 ./...    # (make test)

go test -run Example -v ./internal/rules
